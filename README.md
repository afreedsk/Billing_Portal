# Billing Portal

A role-based billing/finance portal.

- **Frontend:** React + Vite + hand-written CSS (`src/index.css`, `src/pages/Login.css`) + Recharts
- **Backend:** Flask + Flask-JWT-Extended + SQLAlchemy + openpyxl
- **Database:** MySQL

Single login page → the app reads the logged-in user's `role` and automatically
routes them to the right dashboard:

| Role        | Route               |
|-------------|----------------------|
| SuperAdmin  | `/dashboard/admin`   |
| IT          | `/dashboard/it`      |
| PCM         | `/dashboard/pcm`     |
| MedTech     | `/dashboard/medtech` |
| Caredx      | `/dashboard/caredx`  |

## Backend routes — one dedicated file per department

Each department has its own standalone route file (no shared/generic
blueprint), matching its own fields and category rules:

| File | URL prefix | Notes |
|---|---|---|
| `routes/it.py` | `/api/it` | Income/Expenses · Categories: Web Services, Portal Services, Others · Revenue Type · Generated By |
| `routes/pcm.py` | `/api/pcm` | Income/Expenses · Categories: Aya, Care Taker, Nurse, RMP, Physico Care · no Revenue Type / Generated By |
| `routes/medtech.py` | `/api/medtech` | Income/Expenses · Categories: Retail, Wholesale · Revenue Type · Generated By |
| `routes/caredx.py` | `/api/caredx` | Lab Data Entry module + standalone Expenses tracker (see below). No generic Income/Expenses finance module for this department. |
| `routes/superadmin.py` | `/api/admin` | User management, team stats, platform overview |
| `routes/auth.py` | `/api/auth` | Login / current-user |

## Caredx — Lab Data Entry + Expenses (replaces the generic Finance module)

Caredx does **not** use the generic Income/Expenses finance module that
IT/PCM/MedTech use. Instead its dashboard is built from two dedicated
tables that together drive the stat cards and charts:

**1. Lab Data Entry** — the department's day-to-day patient/test log, with
these exact columns:

`Date · Name of the Patient · Name of the Test · Total Amount Paid · Name of
the Employee · Cash · Online · Paid to Other Labs · RMP · Salaries/Expense ·
Details of Expenses · Referral By (Who) · Amount of the Referral · Sales`

- **Add / Edit / Delete** entries individually via the "Add Entry" form
- **Import Excel** — upload a `.xlsx` matching (or close to) the department's
  tracker layout; every valid row is inserted straight into the database.
  The header-matching is tolerant of typos/spacing (e.g. "Detalis of
  Expenses", "name of the empolye") so the existing sheet can be dropped in
  as-is. Rows missing a Date or Patient Name are safely skipped and reported
  back rather than guessed at.
- **Export Excel** — downloads the currently filtered entries as a
  professionally formatted `.xlsx` (header styling, currency format, frozen
  header row), ready to send or re-import elsewhere.
- Backend logic lives in `backend/excel_utils.py`.

**2. Expenses** — a simple Category + Amount tracker (e.g. "Lab Chemicals",
"Syringe Box", "Pamphlets Distribution") matching the department's own
expenses list. Add/Edit/Delete via its own form; category is free text with
autocomplete suggestions from past entries.

**Dashboard stat cards:** Total Amount Paid · Total Cash · Total Online ·
Paid to Other Labs · Total Sales · Expenses.

**Charts:**
- *Income vs Expenses Trend* — Income = Lab Data Entry's Total Amount Paid
  per day; Expenses = the Expenses tracker per day.
- *By Category* — Expenses grouped by category.

Both come from a single combined endpoint, `GET /api/caredx/lab-entries/summary`,
so the whole dashboard stays in sync off one shared date-range filter.

## Setup

### 1. MySQL

```sql
CREATE DATABASE billing_portal CHARACTER SET utf8mb4;
```

### 2. Backend

```bash
cd backend
python -m venv venv
source venv/bin/activate        # Windows: venv\Scripts\activate
pip install -r requirements.txt

cp .env.example .env            # then edit DB_USER / DB_PASSWORD / secrets

python seed.py                  # creates tables + 5 demo logins (printed to console)
python app.py                   # runs on http://localhost:5000
```

### 3. Frontend

```bash
cd frontend
npm install
cp .env.example .env            # VITE_API_URL=http://localhost:5000/api
npm run dev                     # runs on http://localhost:5173
```

### 4. Add your logo

Drop your logo file into `frontend/public/primaria.png`. The login page
references it as `/primaria.png` — Vite serves everything under `public/`
from the site root. If the file isn't there yet, the page falls back to a
plain icon automatically, so nothing breaks in the meantime.

## Notes on security for production

- Set strong random values for `SECRET_KEY` and `JWT_SECRET_KEY` in `.env`.
- Serve the backend over HTTPS and set `FRONTEND_ORIGIN` to your real domain.
- Consider shortening `JWT_ACCESS_TOKEN_EXPIRES_HOURS` and adding a refresh-token flow.
- Add rate limiting to `/api/auth/login` to slow down brute-force attempts.
- The Excel import endpoint trusts any authenticated Caredx/SuperAdmin user;
  if multiple people can log in as Caredx, consider adding an audit log of
  who imported what and when (the `created_by_id` column is already there
  to support this).
